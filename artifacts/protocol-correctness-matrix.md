### A10. Bonding Curve Calculation

**Formula (constant product): `virtual_token_reserves * virtual_sol_reserves = k`**

**Buy** (`get_buy_token_amount_from_sol_amount`):
```
input_after_fee = amount * 10000 / (total_fee_bps + 10000)
tokens_out = input_after_fee * virtual_token_reserves / (virtual_sol_reserves + input_after_fee)
tokens_out = min(tokens_out, real_token_reserves)
```
✅ Matches Uniswap V2 constant product formula. Fee is applied to input before swap.

**Sell** (`get_sell_sol_amount_from_token_amount`):
```
sol_gross = amount * virtual_sol_reserves / (virtual_token_reserves + amount)
fee = sol_gross * total_fee_bps / 10000
sol_out = sol_gross - fee
```
✅ Matches Uniswap V2 constant product formula. Fee deducted from output.

### B8. AMM Math (Constant Product)

**Formula: `base_reserve * effective_quote_reserve = k`** (where `effective_quote_reserve = vault_balance + virtual_quote_reserves`)

**Buy base input** (`buy_base_input_internal_with_fees`):
```
numerator = effective_quote_reserve * base
denominator = base_reserve - base       // output base removed from pool
quote_in = ceil_div(numerator, denominator)
// Add fees: lp_fee + protocol_fee + creator_fee
total_quote = quote_in + lp_fee + protocol_fee + creator_fee
```
✅ Standard CP AMM buy formula.

**Buy quote input** (`buy_quote_input_internal_with_fees`):
```
effective_quote = quote * 10000 / (10000 + total_fee_bps)  // fees pre-deducted
input_amount = effective_quote - 1                          // rounding safety
base_out = base_reserve * input_amount / (effective_quote_reserve + input_amount)
```
✅ Standard CP AMM formula with fee-on-input approach.

**Sell base input** (`sell_base_input_internal_with_fees`):
```
quote_out = effective_quote_reserve * base / (base_reserve + base)
// Deduct fees from output
final_quote = quote_out - lp_fee - protocol_fee - creator_fee
```
✅ Standard CP AMM sell formula. LP fee deducted from output (LP provider retains LP fee).

**Effective quote reserves** (`pumpswap_types.rs:effective_quote_reserves`):
```
i128::from(quote_vault_balance)
    .checked_add(virtual_quote_reserves)
    .and_then(|r| u64::try_from(r).ok())
    .filter(|r| *r != 0)
```
✅ Matches vault docs: `effective_quote_reserves = pool_quote_token_account.amount + Pool::virtual_quote_reserves`

### D9. Bonding Curve / AMM Math (Constant Product)

Both `utils/calc/bonk.rs` and `utils/bonk.rs` implement constant product formula: `(virtual_quote + real_quote) * (virtual_base - real_base) = k`.

**Buy** (`get_buy_token_amount_from_sol_amount` in `utils/calc/bonk.rs`):
```
// Input = amount_in (SOL/quote)
protocol_fee = amount_in * 25 / 10000      // 0.25%
platform_fee = amount_in * 100 / 10000     // 1.0%
amount_in_net = amount_in - protocol_fee - platform_fee

input_reserve = virtual_quote + real_quote
output_reserve = virtual_base - real_base

amount_out = amount_in_net * output_reserve / (input_reserve + amount_in_net)
amount_out -= amount_out * slippage_bps / 10000   // slippage protection
```
✅ Standard constant product buy. Fees deducted from input before swap.

**Sell** (`get_sell_sol_amount_from_token_amount` in `utils/calc/bonk.rs`):
```
input_reserve = virtual_base - real_base
output_reserve = virtual_quote + real_quote

sol_gross = amount_in * output_reserve / (input_reserve + amount_in)
protocol_fee = sol_gross * 25 / 10000
platform_fee = sol_gross * 100 / 10000
sol_net = sol_gross - protocol_fee - platform_fee
final_amount = sol_net - sol_net * slippage_bps / 10000
```
✅ Standard constant product sell. Fees deducted from output after swap.

**Reverse calculation** (`get_amount_in` / `get_amount_out` in `utils/bonk.rs`):

Also implemented in `utils/bonk.rs`:
- `get_amount_in`: Given desired `amount_out`, calculates needed `amount_in` (including fees + slippage). Used for exact-out.
- `get_amount_out`: Given `amount_in`, calculates expected `amount_out` (including fees + slippage). Used for exact-in dev trade estimation.
- `get_amount_in_net`: Given `amount_in`, returns net after fees (no swap calculation). Used for net input calculation.

### D10. Swap Modes Support

| Swap Mode | Buy | Sell | Mechanism |
|---|---|---|---|
| **Exact-in** | ✅ Supported | ✅ Supported | `BUY_EXECT_IN` / `SELL_EXECT_IN` discriminator |
| **Exact-out** | ✅ Supported | ✅ Supported | `BUY_EXECT_OUT` / `SELL_EXECT_OUT` discriminator |
| **Slippage** | ✅ Applied via calc | ✅ Applied via calc | Both directions apply slippage_basis_points |

- Exact-out buy: `fixed_output_amount` → `BUY_EXECT_OUT` with amount_out + max_amount_in
- Exact-in buy: default → `BUY_EXECT_IN` with amount_in + min_amount_out
- When no `fixed_output_amount` is provided, the SDK auto-calculates `minimum_amount_out` using the bonding curve formula with slippage.

### D11. Known Unsupported Combinations

| Combination | Issue |
|---|---|
| Zero input amount | Rejected at SDK level: "Amount cannot be zero" |
| Sell without `input_amount` | Error: "Bonk sell requires input_amount (token amount to sell)" |
| Other global config values | Only WSOL and USD1 global configs are handled; unknown configs would produce incorrect quote mint routing |

### D12. Price Calculation

The SDK provides `utils/price/bonk.rs` for token price calculation:
- `price_token_in_wsol(virtual_base, virtual_quote, real_base, real_quote)`: Returns f64 price of token in WSOL
- `price_base_in_quote(...)`: Generic price calculation with decimal adjustment
- Formula: `price = (virtual_quote + real_quote) / (virtual_base - real_base) / 10^(quote_decimals - base_decimals)`
